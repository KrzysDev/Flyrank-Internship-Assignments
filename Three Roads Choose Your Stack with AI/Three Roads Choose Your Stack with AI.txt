"## Stack Options

### Option 1 — Simplest: Static HTML/CSS/JS
**How you'd build it:**
- Plain HTML/CSS/JS, 3 pages (index.html, work.html, contact.html) or one page with anchor sections
- Use a simple CSS framework like Pico.css or plain custom CSS (no build step)
- GIFs: just `<img src="demo.gif">` — browsers autoplay GIFs natively
- Image galleries: CSS grid + a lightweight lightbox lib (e.g. GLightbox via CDN)

**Where to host (free):**
- GitHub Pages or Netlify (drag-and-drop or git-connected), both free forever for static sites

**Backend needed?**
- No. Contact "button" can just be `mailto:`, `tel:`, and a LinkedIn link — no form, no server.

**Real trade-off:**
Fastest to ship, zero moving parts, nothing to maintain or break. But you hand-edit HTML for every content change, and GIFs are heavy — large demo GIFs can make Work page load slowly since there's no lazy-loading or optimization out of the box unless you add it yourself.

---

### Option 2 — Middle ground: Static Site Generator (Astro or Next.js static export)
**How you'd build it:**
- Astro (lighter, great for content-heavy portfolio sites) or Next.js in static export mode
- Component-based: Hero component, WorkCard component, ContactCard component — matches your sitemap cleanly
- Convert GIFs to optimized `<video autoplay loop muted>` (much smaller than GIF) or use `next/image`/Astro's image optimization for the galleries
- Contact page: still `mailto:`/`tel:`/LinkedIn links, or add a serverless form (see below)

**Where to host (free):**
- Vercel or Netlify (free tier is generous for personal portfolios), or GitHub Pages if you stick to Astro static output

**Backend needed?**
- No backend server required. If you want an actual "send a message" contact form instead of just mailto, use a free forms-as-a-service like Formspree or Netlify Forms (both have free tiers, no backend code needed).

**Real trade-off:**
More setup (npm, build tooling, component structure) than Option 1, but you get reusable components, better performance (image/video optimization), and cleaner code organization. Slight learning curve if you haven't used a framework before, but very manageable at "intermediate" skill level.

---

### Option 3 — Most powerful: Next.js (full) + optional backend
**How you'd build it:**
- Next.js with App Router, TypeScript optional
- Dynamic Work/Demo page: pull project data from a small JSON/Markdown file or a headless CMS (e.g. free tier of Sanity or Contentful) so you can add future projects without touching code
- Video/gallery: self-hosted optimized `<video>` tags or embed from a free video host (e.g. YouTube unlisted, Streamable) if file sizes get large
- Contact form with real backend logic: Next.js API route (serverless function) that sends email via a free tier email API (e.g. Resend free tier, EmailJS)

**Where to host (free):**
- Vercel free tier (handles both frontend and serverless API routes natively)

**Backend needed?**
- Technically yes — but it's serverless (API routes), not a server you manage. Free tier covers a personal portfolio's traffic easily.

**Real trade-off:**
Most flexible and "professional-grade" (real contact form, CMS-editable content, scalable), but it's overkill for a 3-page portfolio unless you want to practice full-stack skills or plan to expand this into a bigger site later. More moving parts = more that can break, and CMS/email API free tiers sometimes have rate limits worth checking.

---

**My honest read for your case:** given it's 3 fixed pages, GIF/gallery demos, and a static contact list — Option 2 (Astro + Netlify/Vercel) hits the sweet spot. You get clean structure and good performance without backend complexity you don't need."
